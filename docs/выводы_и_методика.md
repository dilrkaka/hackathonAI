# Финальные графики для презентации

Все графики экспортированы в PNG (300 dpi) и SVG. Повторный запуск API не выполнялся; использованы сохранённые результаты benchmark_analysis_bundle.zip.

## 1. Качество поиска
**Вывод:** Smart повышает Precision@4 с 4,2% до 16,3%, а HitRate@4 — с 16,7% до 46,7%. То есть релевантный товар появляется в топ-4 примерно в 2,8 раза чаще.

## 2. Скорость
**Вывод:** Медианная полная задержка Smart ниже: 383 мс против 688 мс у Baseline. P95 также немного ниже — 761 мс против 824 мс.

## 3. Полнота выдачи
**Вывод:** Smart возвращает минимум четыре позиции в `results` во всех 60 запросах и не имеет пустых выдач; у Baseline пустыми оказались 83,3% запросов. Важно: `results` Smart включает основные товары, допродажи и альтернативы; у Baseline поле `results` отсутствует, поэтому для него использован `products`.

## 4. Эффективность по типам запросов
**Вывод:** Smart лучше всего работает на категорийных и точных запросах, а также на запросах с атрибутами. Контекстные запросы, опечатки и сленг остаются слабым местом; показатели отражают совпадения с текущим CSV-эталоном.

## 5. Состав выдачи
**Вывод:** В сохранённых Smart-ответах отмечено 83 основных совпадения, 72 допродажи и 85 альтернатив (240 позиций суммарно). Сравнение с Baseline ограничено: в его сохранённом формате есть только `products`, поэтому отсутствие ролей допродаж/альтернатив нельзя трактовать как доказательство, что алгоритм их не выдавал.

## Методические примечания
- Качество рассчитано по первым четырём элементам `results`; для Baseline, где `results` отсутствует, использован `products`.
- Обычная релевантность: совпадение ID **или** категории. Строгая: если в эталоне заданы ID товаров, засчитывается только совпадение ID; иначе — категория. В сохранённых данных обычные и строгие показатели совпали.
- «4+ товара» — число позиций в соответствующем поле выдачи, не число уникальных товаров.
- Графики отражают один сохранённый прогон из 60 запросов на режим; повторный эксперимент не выполнялся.
