# SoftSearch — техническая документация

Актуальная реализация в ветке `main`. Основной вход приложения — `backend.app.main:app`.

## Поисковый конвейер

1. `backend/app/search/loader.py` загружает товары и категории из PostgreSQL, нормализует характеристики и подсчитывает зарегистрированные клики. Индекс строится лениво при первом обращении и хранится в памяти процесса.
2. `normalize.py` и `typos.py` разбирают запрос, обрабатывают стоп-слова, синонимы, опечатки и раскладку. Стемминг используется внутри поиска; известные полные исправления отображаются отдельно при наличии основных совпадений.
3. `intent.py` распознаёт поддерживаемые намерения (сервер, рабочее место программиста, защита компьютера) и расширяет запрос терминами предметной области.
4. `bm25.py` и `engine.py` формируют кандидатов и ранжируют их с учётом названия, описания, категории, доступности и намерения. Кандидаты группируются по `group_id` (или ID, если группа отсутствует).
5. `characteristics.py` извлекает требования к платформе и сроку лицензии; проверка возвращает `ok`, `mismatch` или `unknown`. Неизвестное значение не доказывает совместимость.
6. `recommend.py` формирует допродажи. Для комплексного рабочего места при наличии обеих групп движок чередует релевантные ноутбуки и ПО; при явном запросе ноутбука физические ноутбуки получают дополнительный приоритет.

## Выдача и API

`POST /api/search/smart` принимает `query`, `limit` (4–20), необязательный `request_id` и `log`.

| Поле | Смысл |
|---|---|
| `products` | Основные совпадения по классификации движка |
| `recommendations` | Допродажи |
| `alternatives` | Альтернативные товары |
| `results` | Общая ранжированная выдача |
| `popular_recommendations` | Отдельный блок товаров с зарегистрированными кликами, если основных совпадений нет |
| `note` | Пояснение выдачи |

Движок стремится заполнить запрошенный лимит, используя допродажи, похожие предложения и дополнительные альтернативы. Если кандидатов нет, основной список может остаться пустым. Четыре товара в выдаче не означают четыре релевантных совпадения. Популярность обновляется при построении индекса; при отсутствии кликов она не выдумывается.

Baseline (`POST /api/search/baseline`) ищет буквальное вхождение запроса через SQL `ILIKE` в название и описание.

## Аналитика и эксплуатация

Веб-приложение сохраняет поисковые запросы и события в PostgreSQL (`search_logs`, `user_events`). При `log: false` поисковый запрос не записывается в аналитику. Идентификаторы событий и запросов используются для защиты от повторной записи. Локальный JSONL-журнал движка не используется веб-загрузчиком.

Запуск, импорт каталога и переменные окружения описаны в [README](../README.md). Swagger доступен на `/docs`. Модульные тесты запускаются из корня:

```bash
python -m unittest discover -s tests -v
```

Для вспомогательных офлайн-скриптов `build_index.py` и `evaluate.py` нужен отдельно подготовленный JSONL-каталог; для production используется PostgreSQL.

## Ограничения

Правила намерений и словари ограничены. Автоматические исправления могут ошибаться; отображение исправлений консервативно. Альтернативы могут быть нерелевантны. Индекс не обновляется после каждого изменения каталога. Производительность под массовой конкурентной нагрузкой не подтверждена. Внешние LLM/embedding API не используются.
