# Умный поиск (ветка feature/search)

## Как это работает
1. **Разбор запроса** (`normalize.py`, `typos.py`): стоп-слова, исправление раскладки
   (`rfcgthcrbq` -> касперский), опечаток (по словарю каталога), синонимы/сленг.
   Синоним добавляется РЯДОМ с исходным словом: «офис» ищется и как «офис», и как «office».
2. **Поиск** (`bm25.py`, `engine.py`): BM25 по всем товарам, затем лучший товар из каждого
   семейства (`group_id`) — в выдаче всегда разные семейства.
3. **Ранжирование**: недоступные товары (цена 0) ×0.6 — они «2-й приоритет»; название содержит
   фразу запроса ×1.3; характеристики совпали ×1.15 / не совпали ×0.5.
4. **Проверка характеристик** (`characteristics.py`): платформа и срок лицензии из запроса
   сверяются с полями товара: `ok` / `mismatch` / `unknown`.
5. **Допродажи** (`recommend.py`): до 3 точных совпадений + допродажи (антивирус, бэкап...),
   совместимые по платформе. Если подходящих меньше 4 — показываем меньше и пишем `note`.
6. **Журнал** (`query_log.py`): каждый запрос пишется в `data/logs/queries.jsonl`;
   `python scripts/report_queries.py` — отчёт о неудачных поисках.

## Намерение и приоритет категорий (`intent.py`)
Запросы-задачи («сервер», «ноут для программиста», «защита компьютера от вирусов») разбираются
по ключевым словам -> намерение (`server`, `dev_laptop`, `antivirus`). Дальше:
- к поиску добавляются слова-подсказки (`expand`), потому что слова «ноут» в каталоге нет;
- товары нужной категории ×1.6 (`INTENT_BONUS`), остальные ×0.6 (`INTENT_OFFTOPIC`);
- «для сервера» при запросе про обычный компьютер ×0.6 (`SERVER_PENALTY`);
- у намерения свои допродажи (`upsell`), совместимость по платформе проверяется в `recommend.py`.
Новое намерение = новый блок в `INTENTS`.

## Минимум 4 товара
`search_full` всегда просит не меньше `MIN_RESULTS=4`. Если точных мало: допродажи -> похожие ->
товары той же категории -> популярные (`FILL_QUERIES`) -> любые доступные. Если в каталоге
меньше 4 подходящих — в `note` честно пишем сколько. Пустой ответ на мусорный запрос выключается
флагом `FILL_WHEN_EMPTY = False`.

## Команды
    python scripts/build_index.py data/raw/<файл>.xml     # собрать индекс
    python scripts/evaluate.py                            # проверка на контрольных запросах
    python -m unittest discover -s tests -v               # автотесты
    python scripts/check_queries.py                       # 3 запроса капитана глазами
    python main.py   ->  http://localhost:8080/api/search?q=kaspersky

## Что можно настраивать (вверху `src/search/engine.py`)
`UNAVAILABLE_PENALTY`, `PHRASE_BONUS`, `MAIN_SLOTS` (сколько «точных» из 4; остальное — допродажи).
